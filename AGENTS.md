# AGENTS.md

## Cursor Cloud specific instructions

This repository is a **zero-dependency static website** (a personal portfolio, served in production via GitHub Pages using the domains in `CNAME`). There is no package manager, build step, backend, database, tests, or lint config.

- Source of truth: `index.html` (homepage with inline CSS/JS), `blog/` (listing at `/blog` plus posts at `/blog/<slug>`), `calendar.html` (Google Calendar iframe), and static assets under `resource/` (`site.css` / `site.js` are shared by blog pages; `markdown.js` / `blog.js` render posts).
- No dependencies to install and nothing to build; there is no update/setup script beyond confirming `python3` is present.
- Run locally by serving the repo root with any static file server, e.g. `python3 -m http.server 8000`, then open `http://localhost:8000/index.html`. In production, GitHub Pages serves the files directly on push to the default branch. Pretty post URLs are directories with `index.html`; links and canonical URLs omit the trailing slash (`/blog`, `/blog/<slug>`). Both forms still resolve on the server.
- **Write posts in Markdown.** Each post is `blog/posts/<slug>.md` with YAML front matter (`title`, `date`, `excerpt` or `subtitle`). The identical HTML shell at `blog/<slug>/index.html` (copy of `blog/_template/`) loads that file in the browser and renders it. `blog/posts.json` is the published slug list (newest first); the listing, homepage `#blog` section, and jump-to palette read titles/dates from front matter. `excerpt` / `subtitle` appears under the title on `/blog`.
- To add a post: (1) add `blog/posts/<slug>.md`, (2) prepend the slug in `blog/posts.json`, (3) copy `blog/_template/` to `blog/<slug>/` with no edits (the slug comes from the URL). Step 3 is so `/blog/<slug>` works with `python3 -m http.server`. GitHub Pages can also render a markdown post via `404.html` if that folder is missing. Markdown supports headings, lists, quotes, fences, tables, links, images, `:::callout` fences, and raw HTML. Do not invent post body copy unless asked.
- **YouTube / LinkedIn embeds:** paste embed iframes as raw HTML. Multi-line blocks must start with a supported tag (`div`, `details`, `section`, etc.) — wrap iframes in `<div class="post-embed-frame">` inside `<details class="post-embed">` for collapsible embeds (see `blog/posts/job-hunting-in-2026.md`). Use YouTube’s embed URL (`youtube.com/embed/...`) and LinkedIn’s feed embed URL (`linkedin.com/embed/feed/update/urn:li:...`). Styles live in `resource/site.css` (`.post-embed`, `.post-embed-frame--yt`, `.post-embed-frame--li`).
- `.nojekyll` stops GitHub Pages from running Jekyll so `.md` files are served raw for the client renderer.
- Interactive features to spot-check: the theme toggle (`[theme]` in the top nav / `#theme-btn`, dark↔light), the command palette overlay (opens via the `[/]` nav item or the `/` key), and the blog listing/post pages. Note that `Ctrl+K`/`Cmd+K` triggers the browser's own search, not the site palette.
- Non-obvious caveats: `calendar.html` embeds a Google Calendar and will show a Google sign-in prompt rather than a calendar (expected). The page also pings an external hit counter (`api.counterapi.dev`) and loads Google Fonts; both are optional and the page renders fine offline via system-font fallbacks.
